# 05. セキュリティ・コンプライアンス

## 法的立ち位置(最重要)

**本サービスは「ユーザー自身の督促業務を効率化するツール」であり、
債権回収の代行ではない。**

この立ち位置を、以下すべての箇所で一貫して維持する:

- 利用規約
- LP・マーケティングコピー
- メール文面
- 顧客対応・FAQ
- 弁護士・司法書士への送客フロー

### 弁護士法 72 条(非弁行為)対策

弁護士法 72 条は、弁護士でない者が「報酬を得る目的」で
「法律事務」を「業として」行うことを禁じている。

本サービスが該当しないための線引き:

| 該当リスクが高い | 本サービスでやらないこと |
|---|---|
| ユーザー名義での催告書作成代行 | テンプレートを提供するのみ、最終文面はユーザーが選択 |
| 内容証明郵便の作成・送付代行 | やらない、送信導線も自社では提供しない |
| 訴状作成・少額訴訟支援 | やらない |
| 債権額の交渉代行 | やらない |
| 債権の譲渡・買取 | やらない |

| 該当リスクが低い(本サービスのスコープ) |
|---|
| ユーザーが自分で考えて自分の名前で送るメールの送信代行(SaaS の SMTP 代行と同じ) |
| 文面のテンプレート提供(ひな形ツールの提供) |
| 期限管理・スケジューリング |
| 遅延損害金の計算ツール(計算機の提供) |
| 弁護士・司法書士への送客(紹介料は業務委託料として固定額) |

### 弁護士監修

- Phase 1 リリース前に、文面テンプレート全体 + 利用規約を弁護士監修(予算 10〜20 万円)
- 監修を受けた弁護士の事務所と継続的な顧問契約 or スポット契約を結ぶ
- 文面の重大変更時は再監修(年 2〜3 回程度を想定)

## 個人情報保護

### 取り扱う個人情報

| データ | 区分 | 保護レベル |
|---|---|---|
| ユーザーの氏名・メール・電話 | 通常の個人情報 | 標準 |
| 取引先(債務者)の氏名・連絡先 | 第三者の個人情報 | 高 |
| 取引先の請求金額・取引履歴 | 営業秘密相当 | 高 |
| 銀行口座番号 | 機微情報 | 最高 |
| クレジットカード | 取り扱わない(Stripe に委託) | - |

### 保護措置

- **転送中の暗号化**: TLS 1.2 以上を強制(Vercel デフォルト)
- **保存時の暗号化**: Supabase Postgres は AES-256 で at-rest 暗号化
- **アクセス制御**: RLS で組織間データ漏洩を防止、開発メンバーの本番アクセスは最小限
- **監査ログ**: `audit_logs` テーブルで全操作を記録、削除不可
- **退会時の対応**: 30 日以内に物理削除(barring 法令上の保管義務)

### プライバシーポリシー記載事項

1. 取得する個人情報の項目
2. 利用目的(請求書管理・リマインドメール送信のみ)
3. 第三者提供の範囲(SendGrid・Stripe・Supabase のみ、目的限定)
4. 保管期間と削除方針
5. ユーザーの権利(開示・訂正・削除請求)
6. 問い合わせ窓口

## 特定電子メール法対応

### 必須項目

すべての送信メールに以下を含める:

1. **送信者(ユーザー組織)の氏名・名称**(本文中 or 署名)
2. **送信者の住所**(署名)
3. **配信停止の通知方法**(フッターのリンク or メールアドレス)

### オプトイン

- 取引先のメールアドレスへの送信は、**ユーザー(発行者)と取引先の取引関係**に基づく
- 取引関係のないアドレスへの送信は禁止事項として規約に明記
- 取引先から配信停止依頼があった場合、ユーザーが即座に対応できるよう
  ダッシュボードに「この取引先への送信を停止」ボタンを設置

## メール送信のセキュリティ

### SPF / DKIM / DMARC

- SendGrid のドメイン認証機能を使い、ユーザーの独自ドメインから送信させる
- 推奨設定:
  - SPF: SendGrid を含める
  - DKIM: 2048 ビット鍵
  - DMARC: `p=quarantine` 以上(段階的に `p=reject` に強化)

### From アドレスの保護

- なりすまし防止のため、`From` ヘッダはユーザー検証済みアドレスのみ
- 検証はマジックリンクをそのアドレスに送って確認
- 検証済みでないアドレスからの送信は UI でブロック

## Webhook セキュリティ

### SendGrid Event Webhook

- ed25519 署名検証を必須化(SendGrid の公開鍵で検証)
- 検証失敗時は 401 を返し、Sentry にアラート

```typescript
import { EventWebhook } from '@sendgrid/eventwebhook';

const ew = new EventWebhook();
const publicKey = ew.convertPublicKeyToECDSA(process.env.SENDGRID_WEBHOOK_PUBLIC_KEY!);
const valid = ew.verifySignature(publicKey, payload, signature, timestamp);
```

### Stripe Webhook

- `Stripe.webhooks.constructEvent` で署名検証
- イベントの冪等性を担保(`event.id` を `processed_webhooks` テーブルで管理)

### Vercel Cron

- カスタムシークレットヘッダで認証
- IP allowlist(Vercel の Cron IP のみ)

## DB セキュリティ

### service_role キーの取り扱い

- **絶対にブラウザ・クライアントコードに含めない**
- Server Actions / Edge Functions / API Routes でのみ使用
- Vercel 環境変数で管理、ローテーションは年 1 回

### RLS の徹底

新規テーブル作成時のチェックリスト:

- [ ] `enable row level security`
- [ ] select / insert / update / delete それぞれにポリシー設定
- [ ] `organization_id` カラムを持つこと
- [ ] 開発環境で意図しないアクセスができないことを確認
- [ ] CI で RLS ポリシー未設定テーブルを検出する SQL を実行

### バックアップ

- Supabase の自動日次バックアップを有効化
- 月次で手動 SQL ダンプを取得し、別ロケーション(GCS 等)に保管
- 復旧テストを四半期ごとに実施

## 脆弱性対応

### 依存パッケージ

- Dependabot を有効化、メジャーアップデートは PR でレビュー
- `pnpm audit` を CI で実行、critical / high は即修正
- 月 1 回の定期更新ルーティン

### コードレビュー

- 全ての PR にレビューア 1 名以上(まだ 1 人開発なら AI レビュー = Claude Code に明示的に依頼)
- セキュリティ影響のある変更(認証・RLS・Webhook)は特に慎重に

## インシデント対応

### レベル定義

| レベル | 例 | 対応時間 |
|---|---|---|
| P0 | データ漏洩、サービス完全停止 | 即時 |
| P1 | 一部機能停止、誤送信 | 4 時間以内 |
| P2 | パフォーマンス劣化、軽微なバグ | 翌営業日 |
| P3 | UI 不具合、改善要望 | 計画的に対応 |

### 連絡フロー

1. Sentry → Slack でアラート
2. 亥角さんが内容確認 → 影響範囲特定
3. P0/P1 は β顧客(seed 社)に即連絡
4. 復旧後、ポストモーテムを記録(`docs/incidents/` に作成、Phase 2 以降)
