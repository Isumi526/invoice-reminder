# 06. UI / UX デザインガイドライン

## ブランドパーソナリティ:Tonton

「Tonton」は、ドアを **コンコン** とノックする音、**トントン拍子** の軽さ、
事を **淡々と** 進める姿勢を表す。このパーソナリティを UI 全体に投影する。

- **静かに、しかし確実に**:派手さよりも、毎日きちんと動くことの安心感
- **軽やか、しかし真剣**:重い業務を軽くするが、ふざけない
- **手仕事の温度**:機械的すぎず、ユーザーの代わりに「ノックしている」感覚

## デザイン原則

### 1. 「淡々と」が最大の美徳

このプロダクトは「気が重い業務」を扱う。
ユーザーは催促を楽しんでいるわけではない。むしろ罪悪感や緊張を感じている。

- 派手な色・アニメーション・絵文字は控える
- 「ご請求」「ご入金」など丁寧語を画面上でも使う
- 達成感を煽る演出(紙吹雪・トロフィー等)は使わない
- 機能のメインカラーは落ち着いたトーン

### 2. 操作の取り返しを最大限保証

催促業務は「誤送信」が信頼を一発で破壊する領域。

- 重要操作はすべて二段階確認(ダイアログ + 確認テキスト入力)
- 送信予定の reminder は送信実行 1 時間前まではキャンセル可
- 履歴は必ず残す、編集不可、削除不可
- 「元に戻す」ができない操作は UI 上で明示

### 3. ITリテラシー低めの利用者を想定

ターゲットは「奥さんが経理、社長が現場、専任スタッフなし」の層。

- 専門用語は避ける(「与信」「消込」「ステータス」より「入金確認」「お振込」)
- ボタンは大きめ(モバイルでもタップしやすい)
- 1 画面に詰め込みすぎない、ステップ分割
- 操作の意味をボタン横のヘルプテキストで補足

### タイポグラフィ

```css
:root {
  /* 日本語: 可読性重視 */
  --font-sans: "Noto Sans JP", "Hiragino Sans", "Yu Gothic", sans-serif;

  /* 数字・英字: 信頼感のあるサンセリフ */
  --font-display: "Inter Tight", "Noto Sans JP", sans-serif;

  /* 等幅: 金額・請求書番号 */
  --font-mono: "JetBrains Mono", "Source Code Pro", monospace;

  /* サイズスケール(1.250 perfect fourth) */
  --text-xs: 0.75rem;     /* 12px */
  --text-sm: 0.875rem;    /* 14px */
  --text-base: 1rem;      /* 16px */
  --text-lg: 1.125rem;    /* 18px */
  --text-xl: 1.25rem;     /* 20px */
  --text-2xl: 1.563rem;   /* 25px */
  --text-3xl: 1.953rem;   /* 31px */
  --text-4xl: 2.441rem;   /* 39px */

  /* 行間 */
  --leading-tight: 1.25;
  --leading-normal: 1.6;
  --leading-relaxed: 1.75;
}
```

#### フォント使用方針

- **金額表示**: 等幅(`var(--font-mono)`)+ 右揃え
- **見出し**: `var(--font-display)` + medium weight
- **本文**: `var(--font-sans)` + regular
- **数字とアルファベット**: `tabular-nums` を効かせる

### グリッド構造

- **ダッシュボード**: サイドバー(240px 固定) + メインエリア

### B. 請求書一覧

- フィルター: ステータス / 取引先 / 超過日数 / 金額範囲 / 期間

- 行クリックで詳細モーダル or 詳細画面に遷移
- 一括操作: 「選択して入金確認」「選択してリマインド一時停止」

### D. 新規請求書登録

3 ステップに分割:

1. **取引先選択 or 新規作成**(既存マスタからピックアップ可)
2. **請求書情報入力**(件名・金額・発行日・期日)
3. **確認とリマインドスケジュール確認**

各ステップで「下書き保存」可。

### E. 設定画面

- 組織情報(会社名・代表者・住所・電話・銀行口座)
- 送信者情報(差出人名・メールアドレス・署名)
- リマインド設定(送信時刻・休日スキップ・各ステージのトーン)
- 通知設定(開封通知・バウンス通知の受け取り)
- プラン・請求(Stripe Customer Portal)

## マイクロインタラクション

控えめに、機能的に。

- **読込中**: スピナーではなくスケルトン UI
- **送信成功**: 画面上部にトースト 3 秒、緑系
- **エラー**: 同じくトースト、赤系、自動で消さない
- **遷移**: ページ間は `view-transition` を使用、控えめに
- **入金確認時**: 該当行がふわっとフェードアウトしてから一覧から消える

## アクセシビリティ

- WCAG 2.1 AA 準拠を目標
- キーボードのみで全機能操作可能
- フォーカスリングは `outline` で明示
- スクリーンリーダー対応(`aria-label` を主要ボタンに)
- 色だけで情報を伝えない(ステージは色 + アイコン + 数字)
- フォントサイズはユーザー設定で 1.25 倍まで可

## ライティング・コピー

### トーン

- **丁寧、しかし装飾過剰にしない**
- 「ご請求」「お振込」「ご確認」など接頭辞を保つ
- 「!」は基本使わない
- 「やった!」「お疲れさま!」みたいなテンションを上げる表現は避ける

### ボタンラベル

| 用途 | 良い例 | 悪い例 |
|---|---|---|
| 送信実行 | 送信する | GO! 送信! |
| 入金確認 | 入金確認済みにする | 入金 OK |
| 削除 | 削除する | 消す |
| キャンセル | キャンセル | やめる |

### 空状態(Empty State)

無味乾燥にせず、次のアクションを促す:

```
未払いの請求書はありません ✓
気持ちのいいスタートですね。

[+ 請求書を登録する]
```

## コンポーネント実装方針

- shadcn/ui をベースに、上記トークンに合わせてカスタマイズ
- 各コンポーネントは `components/ui/` 配下
- ドメイン固有コンポーネント(`InvoiceCard` 等)は `components/features/` 配下
- すべて TypeScript + React Server Components 互換
- Storybook は Phase 2 以降に検討

## 参考にしない方がいいもの

- 一般的な SaaS ダッシュボード(Stripe, Linear 風)の派手なグラデーション
- 紫×青のグラデーション(AI 感が出る)
- 過度なアニメーション
- 「ガミガミ系」の催促 UI(赤と黄色だらけ)

## 参考にすると良いもの

- 「無印良品」「カウネット」など、機能美を追求した日本のブランド
- 銀行アプリの落ち着いた配色(三井住友・楽天銀行など)
- 紙のフォーマル感を残した DTP デザイン
