# 04. リマインドフロー・文面ロジック

## ステージ設計

期限前後の経過日数に応じて 5 段階でエスカレーション。

| ステージ | タイミング | トーン | 主な内容 |
|---|---|---|---|
| S1 | 期限 3 日前 / 当日 | やわらかい | ご確認のお願い、振込予定の確認 |
| S2 | 超過 1〜7 日 | 事務的 | お振込状況の確認、再振込のお願い |
| S3 | 超過 8〜14 日 | やや強め | 遅延損害金の発生を予告、連絡を求める |
| S4 | 超過 15〜29 日 | 重要 | 遅延損害金の請求書を再発行、最終確認 |
| S5 | 超過 30 日以上 | 最終 | 法的措置の検討を通知、専門家送客導線 |

## 送信スケジュール(具体)

請求書登録時に以下の reminder レコードを `scheduled` で作成:

```
due_at - 3 days  → S1(事前リマインド)
due_at + 1 day   → S2 初回
due_at + 4 days  → S2 2 回目
due_at + 8 days  → S3 初回
due_at + 12 days → S3 2 回目
due_at + 15 days → S4 初回
due_at + 22 days → S4 2 回目
due_at + 30 days → S5(最終通知)
```

合計 8 通。S5 到達後は手動オペレーションに切り替え(自動送信停止)。

## 送信時刻

- 全ステージとも **平日 09:00〜11:00 JST の間にランダム送信**
- 土日祝は送信スキップ(翌平日にずらす)
- ユーザー設定で送信時刻帯をカスタマイズ可能(Phase 2)

## 文面テンプレート設計原則

### 共通ルール

1. **冒頭の挨拶**: 「いつもお世話になっております。[org.name] の [user.display_name] です。」
2. **件名にステージ感を出さない**: S2 でも「お振込確認のお願い」程度に抑える
3. **金額は税込総額で表示**、内訳も併記
4. **振込先口座**を毎回明記(口座情報の検索手間を省く)
5. **連絡先(電話番号)**を署名に必ず入れる(メール無視層への対策)
6. **トラッキングピクセル**は HTML 版にのみ、テキスト版には入れない
7. **配信停止リンク**を全メールフッターに(特定電子メール法対応)

### トーン基準

- **S1〜S2**: 「お忙しいところ恐れ入ります」「ご確認いただけますと幸いです」
- **S3**: 「お早めのご対応をお願いいたします」「ご事情がございましたらご連絡ください」
- **S4**: 「期日を○日経過しております」「契約に基づき遅延損害金が発生しております」
- **S5**: 「やむを得ず法的措置を検討せざるを得ない状況」「最終のご連絡」

### 禁止表現(脅迫・恐喝と誤解されるリスク)

以下の表現は文面テンプレートから除外:

- 「訴える」「告訴する」「逮捕」「警察」「ブラックリスト」
- 「信用情報に登録」「他社に通報」「自宅まで取り立てに行く」
- 過度な感情的表現(「許しません」「困ります!」)
- 不必要な大文字・赤字・「!」の連打

### 推奨表現(法的措置に触れる場合)

- 「法的措置を含めた対応を検討せざるを得ません」
- 「弁護士に相談のうえ、内容証明郵便等の手段を検討いたします」
- 「契約書記載の通り、遅延損害金が発生しております」

## 遅延損害金計算

```typescript
// 単純計算式(日割り)
function calculateLateFee(
  amount: number,
  annualRate: number,  // 例: 0.03(年率 3%)
  overdueDays: number
): number {
  return Math.floor(amount * annualRate * overdueDays / 365);
}
```

### 利率の根拠

- **商事法定利率**: 年 3%(民法 404 条、2020 年改正以降)
- **契約書で別途定めがある場合**: 契約利率を優先(ただし利息制限法上限を超えない)
- **建設業の慣行**: 年 6% を契約に明記するケースも多い

### 計算タイミング

- 表示時点で動的に計算(DB に保存しない)
- 請求書発行用 PDF を生成する際は確定値をスナップショット保存

## 送信前バリデーション

各メール送信前に以下を必ず実行:

1. **invoice.status === 'active'** であること
2. **debtor.email** が有効(MX レコード確認 + 過去のバウンス履歴チェック)
3. **debtor.is_blocked === false** であること
4. **同一ステージで未送信のものが他にない**か(冪等性)
5. **休日でない**こと(設定で土日祝スキップ)

いずれかが満たされなければ `cancelled` または `scheduled` に戻す。

## 緊急停止メカニズム

ユーザーが「全送信を一時停止」できる組織レベルのフラグを用意:

```sql
alter table organizations add column reminder_paused boolean not null default false;
```

cron 実行時、`reminder_paused = true` の org の reminder はスキップする。
ダッシュボードに「リマインドを一時停止」ボタンを設置(ただし誤操作防止の確認あり)。

## A/B テスト・最適化(Phase 3)

- 開封率の高い件名パターンを学習
- 曜日・時刻による応答率の差分計測
- AI による文面パーソナライズ(取引先の業種・過去履歴を考慮)

ただし Phase 1 では固定テンプレートのみ。最適化は十分なデータが貯まってから。
